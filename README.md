# 网页文章 AI 总结（Online Article Summarizer）

一个 Chrome / Edge 浏览器扩展：在任意网页文章页（微信公众号、少数派、36氪、掘金、个人博客……）**一键调出 AI 侧边栏**，自动把正文喂给 AI，做总结、提炼重点、生成结构化笔记、追问答疑。

- 不开新标签页、不复制粘贴，侧边栏就贴在文章旁边
- 支持任意 OpenAI 兼容协议的模型平台，用自己的 API Key，不经过第三方服务器
- 对话按文章自动归档，同一篇文章下次打开继续聊

当前版本：**v2.1.0**（Manifest V3）

## 它能做什么

打开一篇文章，点一下浏览器工具栏上的插件图标，右侧滑出 AI 侧边栏：

```
┌──────────────────────────┬────────────────────┐
│                          │  📄 文章标题    ⚙️  │  ← 上下文状态 + 设置
│   公众号 / 博客正文        │  [模型：DeepSeek ▾] │  ← 切换模型平台
│                          │                    │
│   （你正在读的文章）        │  用 3 句话总结…     │  ← 快捷问题
│                          │  提炼 5 个重点…     │
│                          │                    │
│                          │  AI 流式回复…       │  ← 边生成边显示
│                          │                    │
│                          ├────────────────────┤
│                          │  ＋新对话 预设 历史  │
│                          │  [输入框]     发送  │
└──────────────────────────┴────────────────────┘
```

跟"把文章复制出来丢给 ChatGPT"相比，它省掉了整个搬运过程，而且**每次追问都带着文章全文**，不会聊着聊着 AI 就忘了原文。

## 主要功能

### 1. 通用文章正文提取（不只是微信公众号）

内容脚本会自动识别页面是不是文章，并抓出：

| 字段 | 说明 |
| --- | --- |
| 标题 | 优先 `og:title` 等 meta 标签，其次正文区 `h1`，兜底用网页标题 |
| 来源 / 公众号 | meta 站点名、`#js_name` 等 |
| 作者 | `article:author`、`.author`、`#js_author_name` 等 |
| 发布时间 | 统一归一化成 `YYYY-MM-DD` |
| 正文 | **DOM 转 Markdown**（保留标题层级、加粗、列表、引用、链接、图片占位） |
| 原文链接 | 自动去掉 `#anchor` 后的干净 URL |

提取策略分两条路：

- **微信公众号快速路径**：用 `#js_content`、`#activity-name` 等专用选择器精准命中
- **通用路径**：先从 meta 标签取元信息，再遍历常见正文容器（`article`、`[role='article']`、`.post-content`、`.article-body` 等），**取文本最长的那个**作为正文

同时会剔除导航栏、页脚、评论区、广告残留、脚本样式，以及 `display:none` / `visibility:hidden` 的占位节点，尽量只留正文。

判定标准：正文有意义文本 ≥ 200 字符才算"文章页"。

### 2. 侧边栏 AI 对话

- **流式输出**：逐字显示，不用等整段生成完
- **随时停止**：生成中可点「停止」中断
- **超时保护**：90 秒没吐出第一个字自动中断，避免页面一直空转
- **Markdown 渲染**：标题、列表、表格、引用、加粗、代码块都能正常排版
- **一键复制回复**：每条回复右下角有复制按钮，复制出来的是清洗过的纯文本，标题层级与模型输出保持一致（`##` 即二级标题），不做自动降级
- **自动过滤思考过程**：模型输出的 `think` 标签会被剥离，只显示正式回答
- **上下文自动同步**：左侧文章切换时，侧边栏会感知并提示，不用手动刷新

### 3. 多平台模型、自定义提示词

- 任意 **OpenAI 兼容** 接口都能接（见下方[支持的 AI 平台](#支持的-ai-平台)）
- 可同时配置多个平台，在侧边栏顶部下拉框随时切换
- 每个平台可单独设置 **baseUrl / 模型名 / API Key**
- 设置页有 **「测试」按钮**，保存前先验证连通性
- **系统提示词**可自定义，覆盖默认的"文章分析助手"人设
- **初始快捷问题**最多 4 条，新文章打开时作为可点击的建议卡片
- **预设提示词**最多 12 条，随时一键插入输入框（适合固定套路，如"改写成公众号推文"）

### 4. 历史对话，按文章归档

- 同一篇文章的对话自动绑定该文章，**下次打开自动恢复**
- 历史面板可查看、切换、删除单条，或「清空全部」
- 每条历史显示标题 + 相对时间（如"3 小时前"）
- 最多保留 **60 条**对话，超出自动淘汰最旧的
- 切到别的文章点开旧对话时，会提示"请先打开原文章页面再继续"

## 安装方法

### 前置要求

- Chrome / Edge 等 Chromium 内核浏览器，**版本 114 或更高**（扩展用到了 `chrome.sidePanel` 侧边栏 API）
- 一个 AI 平台的 API Key（用本地 Ollama 的话不需要）

### 安装步骤

本项目**纯原生 JavaScript，零依赖、无需构建**，直接加载即可：

1. 下载或克隆本仓库

   ```bash
   git clone https://github.com/mdsnalw/Online_Article_Summarizer.git
   ```

2. 打开浏览器扩展管理页
   - Chrome：地址栏输入 `chrome://extensions/`
   - Edge：地址栏输入 `edge://extensions/`

3. 打开右上角的 **「开发者模式」** 开关

4. 点击 **「加载已解压的扩展程序」**

5. 选择本仓库所在文件夹（含 `manifest.json` 的那一层）

6. 安装完成后，点浏览器工具栏的拼图图标，把「网页文章 AI 总结」**固定（Pin）到工具栏**

> 更新代码后，回到扩展管理页点一下卡片上的「刷新」按钮，并**刷新已打开的网页**（旧页面注入的还是老版本内容脚本）。

## 使用方法

### 第一步：配置 AI 平台（第一次用必做）

安装后首次打开侧边栏会提示"还没有配置 AI 平台"，按下面两步走：

**方式 A：点提醒里的「前往设置」**

**方式 B：在扩展管理页点「扩展程序选项」，或在侧边栏点右上角 ⚙️ 齿轮**

进入设置页后：

1. 在「AI 模型平台」区点 **「+ 添加平台」**
2. 选择平台类型（下拉框会自动带出 baseUrl）
3. 填 **模型名**（如 `deepseek-chat`、`gpt-4o-mini`）
4. 填 **API Key**
5. 点 **「测试」** —— 显示"连接成功"说明配置没问题
6. 拉到页面底部点 **「保存设置」**

同一个页面还能顺便改「系统提示词」和 4 条「初始快捷问题」。

### 第二步：打开一篇文章

在微信公众号、少数派、36氪等任意文章页，**点击工具栏上的插件图标**，右侧立即弹出 AI 侧边栏。

顶部会显示当前文章的标题，点标题旁的小图标可以直接跳回原文。

### 第三步：开始总结和提问

- **点建议卡片**：新文章会显示 4 条快捷问题，点一下直接发送
- **自己打字**：输入框里回车发送，`Shift + Enter` 换行
- **用预设提示词**：点底部「预设提示词」，选中即插入输入框（可编辑后再发）
- **换模型**：顶部下拉框切换平台，同一个对话里也能换
- **刷新上下文**：文章有更新（如滚动加载了更多内容）时，点 🔄 重新抓取
- **开新对话**：点底部「＋ 开启新对话」，当前对话自动存进历史
- **回看历史**：点底部「历史对话」，选一条继续聊

### 典型用法

| 场景 | 可以这样说 |
| --- | --- |
| 快速判断值不值得读 | 用 3 句话总结这篇文章 |
| 做读书笔记 | 把文章整理成结构化笔记，保留小标题 |
| 找重点 | 提炼这篇文章的 5 个重点，每条一句话 |
| 找金句 | 文章里有哪些值得引用的金句 |
| 二次创作 | 基于这篇文章的观点，写一条 300 字的公众号推文 |
| 追问答疑 | "作者提到的 XX 数据是怎么推出来的？" |
| 交叉验证 | "这篇文章的结论有哪些前提假设？不成立会怎样？" |

## 数据与隐私

- **没有中间服务器**。你的文章内容和 API Key 直接从浏览器发给你配置的 AI 平台。
- **API Key 存在本地**（`chrome.storage.local`），不随浏览器账号同步。
- **平台配置存在同步存储**（`chrome.storage.sync`），同一浏览器账号多设备可同步（Key 除外）。
- **对话记录存本地**（`chrome.storage.local`），最多 60 条，可随时在历史面板删除。
- 侧边栏的对话上下文会把文章正文发给所选的 AI 平台——**这是使用第三方 API 不可避免的**，敏感文章请自行判断。
- 单次请求最多带 **40000 字符**正文，超长文章会被截断（会标注"文章过长，已截断"）。

## 支持的 AI 平台

只要接口兼容 OpenAI 的 `POST {baseUrl}/chat/completions` 且支持 SSE 流式返回，就能接入。内置了以下常用预设：

| 平台 | 默认 baseUrl | 需要 Key |
| --- | --- | --- |
| OpenAI 兼容 | `https://api.openai.com/v1` | ✅ |
| DeepSeek | `https://api.deepseek.com/v1` | ✅ |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | ✅ |
| MiniMax | `https://api.minimaxi.com/v1` | ✅ |
| Moonshot | `https://api.moonshot.cn/v1` | ✅ |
| OpenRouter | `https://openrouter.ai/api/v1` | ✅ |
| Ollama（本地） | `http://localhost:11434/v1` | ❌ |
| 自定义 | 手动填 | 可选 |

> 用 Ollama 时，如果请求被浏览器拦截，可设置环境变量 `OLLAMA_ORIGINS` 允许扩展来源后重启 Ollama。

## 目录结构

```
.
├── manifest.json      # 扩展清单（MV3），声明权限、内容脚本、侧边栏与设置页入口
├── background.js      # 后台 Service Worker：设置读写、平台管理、AI 请求转发与流式解析
├── content.js         # 内容脚本：识别文章页、提取元信息、正文 DOM 转 Markdown
├── sidepanel.html     # 侧边栏结构
├── sidepanel.js       # 侧边栏逻辑：对话流、模型切换、预设提示词、历史记录、Markdown 渲染
├── sidepanel.css      # 侧边栏样式
├── options.html       # 设置页结构
├── options.js         # 设置页逻辑：平台增删改测、系统提示词、快捷问题
├── options.css        # 设置页样式
└── icons/             # 扩展图标（16 / 32 / 48 / 128）
```

### 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存设置、API Key、预设提示词、历史对话 |
| `scripting` | 页面未注入内容脚本时按需补注入 |
| `sidePanel` | 提供侧边栏界面 |
| `tabs` | 读取当前标签页标题与 URL，绑定对话上下文 |
| `<all_urls>` | 在任意网页上提取文章正文 |

### 消息流转

```
content.js  ──(提取正文)──►  background.js  ──(组装 messages)──►  AI 平台 API
                                     ▲                                  │
                                     └────────(SSE 流式 token)──────────┘
                                     ▼
                              sidepanel.js （渲染）
```

## 常见问题

**Q：点插件图标没反应 / 侧边栏不弹出来？**
A：确认浏览器版本 ≥ 114，且插件已固定到工具栏。如果刚重新加载过扩展，请刷新网页。

**Q：提示"当前页面无法识别为文章正文"？**
A：说明正文少于 200 字符，或者这是个列表页 / 首页而非文章详情。此时侧边栏仍可当普通 AI 聊天用，只是没有文章上下文。

**Q：提示"该平台 API Key 未配置"？**
A：到设置页给对应平台填 Key 并保存。填过一次后，输入框会显示"已保存"占位提示。

**Q：回复一直不出来，最后报超时？**
A：90 秒内没收到第一个字就会中断。常见原因是 baseUrl 写错、Key 失效或额度用尽。建议先在设置页点「测试」排查。

**Q：AI 好像没看到文章内容？**
A：检查侧边栏顶部的上下文状态。如果是"未提取到正文"，点 🔄 刷新；部分站点会把正文放在懒加载容器里，滚动到底再刷新成功率更高。

**Q：换了文章，历史对话点开却打不开？**
A：对话与文章 URL 绑定，需先打开原文页面再恢复该对话。这是防止上下文串台的保护机制。

**Q：文章很长，AI 说内容不全？**
A：单次上下文上限 40000 字符，超出会截断。建议针对长文分段提问，或改用上下文窗口更大的模型。

## 开发说明

- 技术栈：原生 JavaScript + CSS，Manifest V3，**无框架、无依赖、无构建步骤**
- 调试后台脚本：扩展管理页 → 卡片上的「Service Worker」链接
- 调试侧边栏：右键侧边栏 → 「检查」
- 调试内容脚本：在文章页按 F12 → Console（内容脚本的报错会出现在页面控制台）
- 修改内容脚本后记得**刷新网页**；修改其他文件后到扩展管理页点「刷新」
